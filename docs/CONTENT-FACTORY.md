# GoWhereAndWhen daily content workflow

The user authorizes daily publication when source, content, build and deployment checks pass. Work toward useful regional climate coverage and country guides for every destination in the existing 202-record map dataset. Target useful baseline coverage of at least 75% of the 202 destinations (152) within the next month, with wider coverage afterward, without treating the date as permission to lower quality. Start with 1–2 countries per run for the first three successful batches; increase to 3–4 after review, and at most 5–7 only if the measured runtime, source quality, mobile checks and budget support it. A failed batch resets the increase until repaired. This is a quality-controlled rollout, not a daily page quota or a claim that everything is already covered.

Run `node scripts/content-coverage.cjs` after data updates to regenerate `docs/content-coverage.json`. Prioritize international visitor popularity using docs/destination-priority.json, then reader questions within each destination. Start France, Spain, USA, Turkey, Italy, Mexico, UK, Germany, Japan and China, using the dated comparable arrivals table and noting its estimate for China. Keep private analytics reports and personal travel plans out of tracked/public files. The inventory script deliberately does not certify research quality or overwrite the release log.

## One complete daily batch

1. Inspect repository instructions and user changes. Fetch current production from `https://github.com/tooaverage/gowhereandwhen`, preserve unrelated work, and avoid overlapping writers. Use a separate checkout if necessary. Never force-push or overwrite a user's uncommitted edits.
2. Pick the next incomplete country in arrivals-priority order. Finish and validate each country independently within the batch. Improve one existing guide or add a genuinely useful missing guide; extend the reusable build pipeline where needed. Choose travel bases first using comparable official arrivals or overnight-stay data, recurring traveller recommendations and independent guide cross-checks. Keep the metric, year and geographic unit explicit; missing votes are not zero, and Reddit scores are not visitor counts. For larger countries cover worthwhile destinations across regions, not arbitrary evenly spaced weather samples. Small city-states may need only one sample. Choose a defensible sample count for the country's geography; do not call interpolation full-resolution climate coverage.
3. Fetch traceable official climate data. Store city coordinates, provider, reference period, request URL, units and derivation. Prefer station normals where practical; identify gridded reanalysis accurately. Use daily-average highs/lows and calendar-month precipitation totals. Never substitute monthly extreme temperatures for average highs. Complete all twelve months and validate units, missing values, plausible ranges, high >= low and coordinate locations. Do not invent missing data or reuse one city for several regions.
4. Add useful editorial detail supported by current tourism, park, transport and meteorological sources: regional seasons, city comparisons and a practical backpacker route when applicable. Plan separate stop lists and night allocations for each trip length; do not proportionally stretch a short route to fill a month. Account for transit and why each stop merits its stay. Verify travel legs rather than drawing fictional direct connections. Date prices if used, explain uncertainty, and do not claim firsthand visits or live availability. Weather comfort is not a safety, visa, storm-warning, skiing or sea-condition recommendation.
5. Keep the country page as the overview. Add a child city or itinerary URL only if it provides substantial distinct help. Candidate patterns are `/country/france/paris/` and `/country/france/routes/14-days/`; implement routing/canonical/sitemap support before publishing any child page. Do not create every city-month permutation, duplicate summaries or filler pages. Do not replace established URLs. Maintain useful contextual internal links and only update lastmod for materially changed pages.
6. Preserve the fixed absolute 0-100 travel weather scale. An all-poor country remains red; no per-country or per-month min/max stretching. Country boundaries and missing-data coverage remain explicit. Best-weather windows can be relative to a city's year, but must never imply that its top month is objectively ideal.
7. Regenerate with `python3 storybook-lab/build.py`, then `npm run build && npm run check`. The current build supports 74 guides and 89 canonical pages; when deliberately adding a guide, update dependent generators and assertions together, retaining checks for exact expected output, canonical uniqueness, working links, metadata and indexing. Never weaken tests just to permit a failed build. Compare mobile/desktop rendering and the changed city/month/map interactions for material UI changes.
8. Review the diff and public output for unrelated changes, incorrect facts, private data and source attribution. Commit only relevant source and generated files, push normally to production main, and verify the corresponding GitHub Pages deployment and public content. On failure, repair or leave the batch unpublished. Do not label unpublished work as launched. If a completed commit is waiting on publication, finish it before starting another batch.
9. Notify the user only about a meaningful launch, failure, blocker or decision needing their attention. Include the changed destinations and working URLs. Stay quiet for unchanged/non-actionable checks. Keep each day's work bounded; quality takes precedence over shipping every day.

PostHog project 613152 is the site's analytics project. Respect opt-out and GPC settings. Analytics now uses memory-only IDs; count pageviews and interactions, not unique people or reliable returning visitors. Treat the 2026-09-26 tracking change as a measurement break. Track map interaction, city selection, guide opening and booking referrals. Booking clicks are not completed bookings or revenue. Search Console access and indexing are separate and must be verified, not assumed.

During weekly prioritization, review accessible search impressions/clicks and landing-page engagement. Without access, report missing evidence instead of inventing growth. Use findings to improve pages people already discover. Prepare a shareable monthly map or a small destination comparison when useful, but do not send outreach, post to communities, buy ads, create accounts or spend money without user instructions. A content schedule alone is not a distribution strategy.

## Concision and distinct value (release gates)

Lead with the answer. Use a one or two sentence overview, compact month/city comparisons, and short practical route notes. No word-count minimum, repeated introductions, generic travel filler, or keyword variants written as separate sections. Expand only to answer a distinct traveller question. User-facing launch reports should usually stay under 120 words.

Before adding a URL, state its specific search intent and the existing page it could overlap with. Compare its main content with the closest existing pages, ignoring shared navigation, footer and factual labels. Reject country-name substitutions and repeated substantive paragraphs. Shared layout and common factual terms are fine. Distinct value must come from sourced local climate contrasts, route constraints, transport or seasonal decisions, not synonyms. If there is no separate need, improve the existing page. Use self-canonicals for genuinely distinct pages; consolidate actual duplicates rather than canonicalizing every child to its parent. Never create indexable month/filter permutations. No guaranteed rankings or invented similarity percentage thresholds.

## Weekly SEO learning and content marketing

Reserve a short part of Monday's run for learning and marketing alongside the country batch; reduce country count if needed to stay within the configured budget. Read `docs/seo-learning.md`. Review current primary Google Search Central guidance only for a relevant change or open question. With Search Console access, inspect indexing, queries, landing pages, impressions and clicks; compare completed 28-day periods where available. Without access, log the missing source and continue useful technical/editorial checks. Never mistake `site:` results for a complete indexing report.

Choose at most one hypothesis and one small change. Record baseline, affected pages, date, expected outcome and review date. Wait at least 28 days for search observations, longer with sparse data, and distinguish seasonality and tracking changes from causation. Classify results as supported, rejected or inconclusive. Improve the workflow only on evidence, not a single noisy fluctuation. Keep private raw metrics outside tracked files, for example ../private-marketing/ (never publish it). Store only non-sensitive lessons in docs/seo-learning.md.

Create one compact marketing pack using already verified site facts: a seasonal destination comparison, one shareable map view/link, two short social drafts and a suggested relevant audience. Save private drafts outside the deployed repository. Do not automatically post to accounts, contact communities, send emails, buy ads or create accounts. On the first Monday of a month, prefer updating one evergreen “where to go in [month]” resource with meaningful climate comparisons, provided it has distinct intent and routing/indexing support. Publishing useful site content is authorized after the normal gates. Refresh a worthwhile existing resource before making a near-duplicate. Keep one scheduled run per day; avoid separate overlapping writers.

## Writing and design rule: less is more

Use Japan as the country-page reference: shared city-by-month map, trip-length route map, typography and controls. Roll these components into each country as sourced local data is added. Do not invent climate data to fill a template.

Aim for grade 6 reading level. Use plain words, short sentences and one useful idea per paragraph. Lead with the answer. Prefer a map, month badge, short stop list or labelled icon when it makes a decision easier. Remove repeated caveats and filler. Keep sources and detailed methods in an accessible expandable note; keep any limitation needed to interpret a score next to it. Say “Travel itinerary” or “Travel route”, not “Backpacker”, unless the content is specifically about backpacking. Check heading spacing and card rhythm on mobile and desktop. Country-specific advice must remain accurate after shortening.

Future backlog: genuinely seasonal itineraries by month, using existing country pages first. Do not create twelve near-duplicate pages. Monetization changes are separate future work. AI-search referrals are an outcome to measure, never a promised result.

Read [COPY-RULES.md](COPY-RULES.md) before writing or editing visitor-facing content. It is the maintained copy rule and ratchet log. SEO is the growth priority; useful, sourced answers determine length. Track site-wide adoption in checked batches. These editorial rules still require review, not just a passing build.
